TDB JOGOS v6.1.2 — Screen Share Route Fix

CAUSA DO ERRO DA v6.1.1
- o backend tinha a rota platform/screen-share registrada
- porém vercel.json NÃO publicava /api/platform/screen-share
- resultado em produção: HTTP 404 ao tentar anunciar ou consultar a transmissão
- por isso o navegador conseguia abrir o seletor de tela, mas o TDB não conseguia publicar a transmissão na sala

CORREÇÕES
- adicionado rewrite /api/platform/screen-share -> /api/router?route=platform/screen-share
- cliente ganhou fallback direto para /api/router se a rota amigável responder 404
- resposta vazia/HTML de rota inexistente também é detectada como erro
- antes de abrir o seletor de tela, o TDB faz um preflight no servidor
- se o servidor não estiver pronto, a janela de seleção nem é aberta
- mensagens claras para 404, sessão inválida, manutenção, limite de requisição e captura bloqueada
- depois que a tela é escolhida, a prévia aparece imediatamente
- botão PARAR aparece imediatamente, antes da confirmação do servidor
- START precisa confirmar o mesmo broadcastId criado pelo navegador
- fluxo P2P/offer/answer/heartbeat da v6.1.1 foi preservado

FLUXO NOVO
Compartilhar tela
→ Verificando servidor
→ seletor nativo do navegador
→ prévia local + PARAR
→ servidor confirma START
→ usuário da sala vê Visualizar transmissão
→ WATCH
→ OFFER
→ ANSWER
→ vídeo WebRTC

TESTES

- rota HTTP completa validada:
  autenticação → sala → GET state → START → WATCH → STOP
- serviço de sinalização validado
- regressões anteriores preservadas
